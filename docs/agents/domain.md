# Domain docs

Use a single domain context for this repository.

## Before exploring

Read the root `GLOSSARY.md`, when present, and relevant decisions in `docs/adr/`.

If a root `GLOSSARY-MAP.md` is introduced later, follow its pointers to the relevant context glossaries and ADR directories.

If these files do not exist, proceed silently. Create domain documents when terms or decisions are resolved through domain modeling.

## Vocabulary

Use glossary terms in issue titles, proposals, hypotheses, and tests. When a needed term is missing, reconsider the wording or note the gap for domain modeling.

## Decisions

Surface conflicts with existing ADRs explicitly, identify the ADR, and explain why its decision should be reconsidered.
